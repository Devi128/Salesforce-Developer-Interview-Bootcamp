# Challenges Faced

During Day 1, I faced the following challenges:

### 1. Understanding Salesforce Objects
Initially, it was difficult to understand the difference between
standard objects and custom objects.

### 2. Designing the Data Model
I had to decide which business entities should be represented
as separate objects.

For the Placement Management System, I identified:

- Student
- Company
- Job
- Application
- Offer Letter

### 3. Understanding Relationships
Understanding how Student, Job, Company, Application, and
Offer Letter records should be connected was challenging.

### 4. Creating the Correct Fields
I had to determine which fields were required for each object
and what type of field should be used.

### 5. Required Fields
I initially faced confusion when a field continued to appear
as required while creating sample data.

I learned that field-level requirements affect whether a record
can be saved.

### 6. App Navigation
Initially, newly created objects were not visible in the
Placement Management App navigation.

I learned that creating an object does not automatically mean
it appears in the application's navigation menu.

### 7. Understanding Salesforce Metadata
I also learned that Salesforce objects and other components
are metadata and can be retrieved into VS Code.

---

# How I Overcame the Challenges

- Studied the Salesforce data model.
- Created objects one at a time.
- Added fields according to business requirements.
- Configured relationships between objects.
- Added required objects to the application's navigation.
- Tested records after creating each object.
- Retrieved Salesforce metadata into VS Code.

---

# Key Lesson

The biggest challenge was not creating the objects themselves.

The difficult part was understanding **how the business should
be represented as a Salesforce data model**.

I learned that good Salesforce development starts with a good
data model.
